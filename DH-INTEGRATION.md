## Architecture Overview

### What is Distant Horizons?

Distant Horizons is a Level of Detail (LOD) rendering mod that extends Minecraft's view distance by rendering simplified distant chunks. It consists of:

- **Core module** (~532 Java files): Platform-independent rendering, data structures, and LOD generation logic
- **API module** (included in core): Public API for third-party integration
- **Common module** (~67 Java files): Shared code between mod loaders (Fabric/Forge/NeoForge)
- **Fabric module** (~35 Java files): Fabric-specific integration and platform implementations

**Total source files**: ~634 Java files across all modules

### DH's Build System Requirements

DH uses a sophisticated multi-loader build system that differs significantly from MattMC's approach:

```
DH's Build System:
├── Architectury Loom 1.10 - Multi-loader development environment
├── Fabric Loom 1.10 - Fabric-specific build tooling
├── Manifold Preprocessor - Version-specific code generation
├── SpongeGradle - Access widener processing
├── Shadow Plugin - Dependency shading
└── Forgix - Multi-loader JAR merging
```

```
MattMC's Build System:
├── Standard Gradle Java plugin
├── Custom source sets for Fabric Loader, Sodium, Iris
├── Direct Mojang official mappings (no intermediary)
└── Manual dependency management
```

### Key Architectural Differences

| Aspect | Distant Horizons | MattMC |
|--------|------------------|--------|
| **Mappings** | Mojmap + Parchment (parameter names) | Mojmap only |
| **Mod loader** | Multi-loader (Fabric/Forge/NeoForge) | Fabric only |
| **Build system** | Architectury Loom + plugins | Standard Gradle |
| **Access widening** | Automated via Loom | Manual source modification |
| **Mixin refmaps** | Auto-generated by annotation processor | Not generated |
| **Version support** | Multi-version via preprocessor | Single version |
| **Dependency model** | Fabric API modules required | Integrated into main JAR |

### Integration Challenge Summary

The fundamental challenge is bridging these architectural differences:

1. **Mapping mismatches**: DH expects Parchment parameter names; MattMC uses raw Mojmap
2. **Platform abstractions**: DH's multi-loader code expects platform-specific implementations
3. **Preprocessor directives**: Version-specific code needs preprocessing or manual selection
4. **Fabric API dependencies**: DH requires Fabric API modules that MattMC doesn't include
5. **Build tool differences**: DH's sophisticated build plugins aren't present in MattMC
